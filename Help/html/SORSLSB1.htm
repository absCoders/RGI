Sales & Bookings Report

Sales & Bookings Report

This function produces a report showing sales and bookings activity, month and year to-date, compared to budget.  Other features are a bookings backlog by month, projected sales for the month, lost sales, orders in pick (released to the warehouse and not yet shipped), and total open to ship for the current month.

This function may be run at any time.  There is no update process associated with this function.

Please review the General Notes for Reports, for features which are common to all report functions.

General Information

Order booking information is generated by the following:

  • Sales Order Entry
  • On Order (Purchase Orders and Work Orders)
  • Planned (MRP Plans)

Demand information is comprised of the following:

  • Shipment Forecast
  • Component Commitments from Make Purchase Orders
  • Component Commitments from Make Plans

Order booking statistics sensitive to the following critical fields in the order header with respect to time:

  • Date Booked (actually, the date that the order was entered into the order header table)
  • Ship Date (the date that the customer requests shipment of the order, or the date that we calculate that we must ship the order in order to make the customer's requested delivery date)

All values are Net Price Bookings (i.e., not Retail, and after any off-invoice pricing promotions).  The values used are the amounts that will print as the net due for merchandise when the order ships and an invoice is created.

Report Columns

Please note that some of these columns may have modified definitions depending upon the values specified for some of the run-time options, described below.

Monthly Bookings

A

 Carried Forward Booked to ship in a previous month, but not shipped as of that start of the current month

B

 Previously Booked Booked during a previous month to ship in the current month

C

 Currently Booked Booked in the current month to ship in the current month

D

 Future Booked Booked in the current month to ship in some future month.  Any order which contributes to this column, will also contribute to one of the backlog columns at the far right of the report.

E

 Total Booked The total booked to ship this month.  A + B + C

F

 MTD Shipped Shipped Month-to-Date, from all warehouses, combined

MTD Comparisons

G

 Month Budget Total value budgeted to be shipped this month.  This value will appear only if a sales budget has been prepared and loaded into the system.  Sales budgets are by Customer, Store, Brand, and Basic/Promo, and will appear only if the level of detail used to prepare this report does not reach beneath the level of detail for the budget; for example, sorting this report by Item will produce a 0 budget, since budgets are not created down to the item level

H

 TY MTD Shipped Total amount shipped this month-to-date

I

 LY Month Shipped Total amount shipped this month, last year, in total.  Note that this is a total month number, and not month-to-date.

Excess On Hand

J

 Excess Qty Excess Qty on Hand, Units, defined as On Hand less Total Demand: (D - ((G - F) + H + I); if F > G, then 0 is used for (G - F)

K

 Excess Value Excess Value On Hand, Dollars: (J * C)

Supply

L

 On PO Total Qty on Open PO's, where the date required is up thru the last day in the forecast horizon

M

 Plans Total Plans from MRP, where the date required is up thru the last day in the forecast horizon

Excess On Order/Plan

N

 Excess Qty Excess On Order/Plan, Units

O

 Excess Value Excess Value On Order/Plan, Dollars: (N * C)

User Interface

Run-Time Options

A page 0 will print (before the report) which summarizes all of the Report Sorting, Filtering, and other run-time options selected.  Some of the run-time options may be reflected in the heading area of the page.

Report Sorting

You may sort the report by any of the following:

  • Division
  • Brand
  • Product
  • Item Category
  • Parent Item
  • S/N/U
  • Basic/Promo
  • Make/Buy
  • Excess/Obsolete
  • Item Class

Please note that you must select Excess/Obsolete in order to see separate totals for Excess and Obsolete.  Select the Excess/Obsolete sort break at the point that makes sense for the report you would like to create.  If you would like to see Excess Inventory by Division with a grand total for Excess, followed by Obsolete Inventory by Division with a grand total for Obsolete, then select Excess/Obsolete first, and Division next.  If you would like to see each Division broken down into Excess/Obsolete with Division totals for both, then select Division first, then Excess/Obsolete next.

Report Filtering

You may filter the report to include all, selected, or (all) except specific values of the following:

  • Division
  • Brand
  • Product
  • Item Category
  • Parent Item
  • Market
  • Item Class
  • S/N/U
  • Basic/Promo
  • Make/Buy

Number of Periods of Demand to Consider (to define the Forecast Horizon)

Enter the number of months of demand to consider when calculating excess and obsolete values.  The current month is counted as the 1st period of demand.  If running the report in the middle of the month, then the current month's remaining forecast is used, as well as the present values for quantities on hand, on order, and committed to production.  If the current month's shipments exceed the total forecasted demand for the number of months specified, then zero is used for forecast remaining.

The report is rendered in real-time, all date and period math is calculated with reference to the Current Operations Period.  All On Hand, On Order, Shipment and Commitment data is produced in real-time, as of the moment the report is printed.

Single Warehouse

You may select a single warehouse to be used in the calculation of Excess and Obsolete values.  If you do select a single warehouse, then only the forecasts for those markets associated with that warehouse are used for demand, and only those on hand quantities listed in that warehouse, and on order and plan quantities headed for that warehouse are used for supply.  Also, MTD shipments will reflect only the single warehouse.

Calculation of Forecasted Demand

Forecast data is optionally taken from any one of the following, specified at run-time:

  • Forecast by Item by Market (includes Past Due Forecast)
  • Sales History for the Most Recent X Months (using the quantity shipped by item, for the last X months, where X is the number of periods selected as the forecast horizon)
  • Sales History for Last Year (using the quantity shipped by item, for the X months starting 12 months ago - note that you should not use a forecast horizon of more than 12 months when using this option)

Show items with Excess/Obsolete On-hand, On-Order, or Either

You may request to see items with Excess/Obsolete On Hand, On Order, or either.

Show Excess Items Only, Obsolete Items Only, or Both

You may request to see items which are Excess only, items which are Obsolete only, or both, on the same report.

Include Plans in Calculations

You may optionally include Plan Data for Supply and/or Demand statistics used to calculate the Excess/Obsolete values.  Be sure to have run MRP Update recently if you select this option, since MRP update re-calculates MRP plans and component commitments based upon real-time inventory status.  Also note that if an item is missing critical MRP data, it might not have plans generated for it, or commitments generated for it's components, and this might have in impact on an item's excess or obsolete categorization.

Exclude Items in Non-MRP Warehouses

You may optionally exclude all Supply & Demand data that is associated with warehouses which are marked as Non-MRP Warehouses.  If selected, then On Hand, MTD Shipment, On Order, Planned, and Component Commitment quantities in Non-MRP warehouses will be ignored.  Also, forecasts for markets that are associated with Non-MRP warehouses will also be ignored.

Sort Items by Excess/Obsolete Value

Items are normally listed alphanumerically, by Item Code, within the last sort level you choose.  However, you may optionally have the items sorted (in descending order) by Excess/Obsolete Value.

Reduce Excess Inventory by Reserves, if Any

You may optionally have the Quantity on Hand reduced by the Reserve Percentage, if present in the Item Master.  This will have the effect of reducing the Excess Inventory for an item by the Reserve, which theoretically is a financial acknowledgement of Excess/Obsolete Inventory.  Most of the time, the Reserve Percentage will be 0 or 100, so the effect of using this option is to remove items from the report if they have been financially written down already.

Report Totals

Totals are shown for Excess/Obsolete Values for On Hand and On Order.  Totals are produced for each sorted level of the report.  Note that if you want separate totals for Excess and Obsolete values, then you must select "Excess/Obsolete" as a sort level.
